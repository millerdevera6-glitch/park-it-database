3. Disaster Recovery Plan & Technical Justification

3.1 Backup Strategy & Format Rationale

The approved logical backup mechanism is pg_dump in the PostgreSQL Custom Archive Format (-Fc). Plain text SQL dumps (-Fp) were rejected because they lack compression, execute strictly sequentially, and cannot be selectively inspected or restored. The -Fc format provides:

  1. Embedded zlib Compression: Minimizes secondary storage consumption.
  2. Indexed Table of Contents (TOC): Enables fast catalog pre-inspection using pg_restore --list without restoring data.
  3. Selective Restoration: Allows restoring specific tables or schemas when handling targeted table-level corruption.
  4. Topological Dependency Reordering: Automatically creates tables prior to foreign keys and indexes, maximizing ingestion throughput.

3.2 Schedule, Retention, RPO, and RTO

Parameter Specification Technical & Operational Rationale
Schedule Daily Full Backup at 01:00 AM Off-peak execution avoids lock contention during operational hours (07:00 – 19:00).
Retention 7 Daily, 4 Weekly, 12 Monthly Grandfather-Father-Son (GFS) model ensures point-in-time rollbacks and audit compliance.
RPO 1 Hour (Peak) / 24 Hours (Off-Peak) Defines acceptable data loss between backup intervals. (Continuous WAL archiving advised for sub-15m RPO).
RTO 30 Minutes Total target duration from incident declaration to database online status.

3.3 PostgreSQL Role & Privilege Recreation (Architecture Requirement)

Critical Principle: PostgreSQL roles (pg_roles) are cluster-wide and are not included in single-database logical dumps. Restoring to a fresh cluster requires provisioning roles first: 

-- 1. Provision Cluster Roles
\i db-access-control/01-create-roles.sql
\i db-access-control/02-role-memberships.sql

-- 2. Restore Database Architecture & Objects
pg_restore -U postgres -d canteendb_restored bwis_activity6.dump

-- 3. Re-establish Database-Level Connect Security (Stripped during logical dump)
\i db-access-control/03-database-privileges.sql

7. Recommendations & Production Readiness

  1. Continuous Archiving (PITR): Supplement daily logical dumps with continuous PostgreSQL Write-Ahead Log (WAL) archiving to eliminate the 24-hour RPO gap.
  2. Automated Database-Level ACL Reapplication: Restoration playbooks must incorporate 03-database-privileges.sql to re-secure pg_database.datacl immediately after restore.
  3. Periodic Automated Drill Pipelines: Implement a weekly CI/CD cron runner executing backup.ps1, restore.ps1, and verification.sql inside an isolated sandbox to detect schema regressions.
