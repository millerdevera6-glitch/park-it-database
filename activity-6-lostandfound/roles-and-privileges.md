## 1. Role Architecture Overview

In PostgreSQL, roles are **cluster-wide entities** stored in the global shared catalog `pg_authid`. Because roles exist at the cluster level rather than within individual database catalogs, they are **never included** in logical single-database backups generated by `pg_dump`.

The PUP-SPOT architecture implements role-based access control (RBAC) to enforce separation of concerns between campus students/guests (public interface) and campus administrators (staff management interface):

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│                       PUP-SPOT ROLE HIERARCHY                               │
├─────────────────────┬──────────────┬──────────────┬─────────────────────────┤
│ Role Name           │ Can Login?   │ Superuser?   │ Architectural Purpose   │
├─────────────────────┼──────────────┼──────────────┼─────────────────────────┤
│ postgres            │ Yes (t)      │ Yes (t)      │ Cluster DBA / Superuser │
│ lostandfound_app    │ Yes (t)      │ No (f)       │ Admin API Backend       │
│ lostandfound_public │ Yes (t)      │ No (f)       │ Public Web API Backend  │
│ lostandfound_backup │ Recommended  │ No (f)       │ Automated Backup Agent  │
└─────────────────────┴──────────────┴──────────────┴─────────────────────────┘
```

## 2. Intended Privileges vs Live Database Privileges

An inspection of the live PostgreSQL catalog (`information_schema.table_privileges`, `information_schema.usage_privileges`, and `pg_roles`) confirmed that the live database privileges match the authoritative SQL script `sql/grp05_lostandfounddb_role_creation_sample_script.sql`:

### A. Admin Application Role (`lostandfound_app`)
- **Connection & Schema:** `CONNECT` on `grp05_lostandfounddb`, `USAGE` on schema `public`.
- **Table Operations:**
  - `SELECT, INSERT, UPDATE` on all tables in schema `public` (`categories`, `items`, `lost_reports`, `claims`, `potential_matches`, `item_images`, `lost_report_images`, `claim_images`).
  - `DELETE` on `potential_matches` (for refreshing/pruning machine match scores).
  - `DELETE` on image metadata tables (`item_images`, `lost_report_images`, `claim_images`).
- **Sequences:** `USAGE, SELECT` on all sequences in schema `public`.
- **Security Boundary:** The role **CANNOT** drop tables, cannot delete primary `items` or `lost_reports`, and cannot alter schema definitions.

### B. Public Web Interface Role (`lostandfound_public`)
- **Connection & Schema:** `CONNECT` on `grp05_lostandfounddb`, `USAGE` on schema `public`.
- **Table Operations:**
  - `SELECT` on `categories`, `items`, `lost_reports`, `claims`, `potential_matches`, `item_images`, `lost_report_images`.
  - `INSERT` on `lost_reports` (submitting new lost notices), `claims` (submitting ownership claims), `potential_matches`, `lost_report_images`, `claim_images`.
  - `UPDATE (status)` column-level privilege on `lost_reports` (allowing students to cancel their own active reports via report code).
  - `DELETE` on `potential_matches` (dismissing a match notification).
- **Security Boundary:** Denied `UPDATE` on item titles/descriptions, denied `DELETE` on `items`, `lost_reports`, `claims`, and `categories`, and denied access to modify database configurations.

## 3. Reproduction & Role Recreation Script

When migrating to a new PostgreSQL server instance or performing a bare-metal disaster recovery, execute the following script as a PostgreSQL superuser **BEFORE** running `pg_restore`:

```sql
-- =============================================================================
-- IDEMPOTENT ROLE RECREATION SCRIPT
-- Execute as 'postgres' superuser on the target PostgreSQL cluster
-- =============================================================================

-- 1. Create lostandfound_app Role
DO $$
BEGIN
    IF NOT EXISTS (SELECT 1 FROM pg_roles WHERE rolname = 'lostandfound_app') THEN
        CREATE ROLE lostandfound_app WITH LOGIN PASSWORD 'ReplaceWithStrongAdminPassword';
        RAISE NOTICE 'Role lostandfound_app created successfully.';
    ELSE
        RAISE NOTICE 'Role lostandfound_app already exists. Skipping creation.';
    END IF;
END $$;

-- 2. Create lostandfound_public Role
DO $$
BEGIN
    IF NOT EXISTS (SELECT 1 FROM pg_roles WHERE rolname = 'lostandfound_public') THEN
        CREATE ROLE lostandfound_public WITH LOGIN PASSWORD 'ReplaceWithStrongPublicPassword';
        RAISE NOTICE 'Role lostandfound_public created successfully.';
    ELSE
        RAISE NOTICE 'Role lostandfound_public already exists. Skipping creation.';
    END IF;
END $$;

-- 3. Create Dedicated Backup Service Role (Recommended Practice)
DO $$
BEGIN
    IF NOT EXISTS (SELECT 1 FROM pg_roles WHERE rolname = 'lostandfound_backup') THEN
        CREATE ROLE lostandfound_backup WITH LOGIN PASSWORD 'ReplaceWithStrongBackupPassword';
        RAISE NOTICE 'Role lostandfound_backup created successfully.';
    ELSE
        RAISE NOTICE 'Role lostandfound_backup already exists. Skipping creation.';
    END IF;
END $$;
```

## 4. Privilege Grant Script

After creating the database and restoring objects via `pg_restore`, execute the privilege synchronization script:

```sql
-- Connect to the target restored database
\c grp05_lostandfounddb_restore_test

-- 1. Database and Schema Usages
GRANT CONNECT ON DATABASE grp05_lostandfounddb_restore_test TO lostandfound_public, lostandfound_app, lostandfound_backup;
GRANT USAGE ON SCHEMA public TO lostandfound_app, lostandfound_public, lostandfound_backup;

-- 2. Grants for lostandfound_app
GRANT SELECT, INSERT, UPDATE ON ALL TABLES IN SCHEMA public TO lostandfound_app;
GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA public TO lostandfound_app;
GRANT DELETE ON TABLE potential_matches TO lostandfound_app;
GRANT SELECT, INSERT, UPDATE, DELETE ON item_images, lost_report_images, claim_images TO lostandfound_app;
GRANT USAGE, SELECT ON SEQUENCE item_images_item_image_id_seq, lost_report_images_report_image_id_seq, claim_images_claim_image_id_seq TO lostandfound_app;

-- 3. Grants for lostandfound_public
GRANT SELECT ON TABLE categories, items, lost_reports, claims, potential_matches, item_images, lost_report_images TO lostandfound_public;
GRANT INSERT ON TABLE lost_reports, claims, potential_matches, lost_report_images, claim_images TO lostandfound_public;
GRANT UPDATE (status) ON TABLE lost_reports TO lostandfound_public;
GRANT DELETE ON TABLE potential_matches TO lostandfound_public;
GRANT USAGE, SELECT ON SEQUENCE lost_reports_report_id_seq, claims_claim_id_seq, potential_matches_match_id_seq, lost_report_images_report_image_id_seq, claim_images_claim_image_id_seq TO lostandfound_public;

-- 4. Grants for lostandfound_backup (Read-Only)
GRANT SELECT ON ALL TABLES IN SCHEMA public TO lostandfound_backup;
GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA public TO lostandfound_backup;
```
