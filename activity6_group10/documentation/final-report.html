2. Project Overview & Architectural Foundation

BoardTrack is a Node.js property management application built on Express 4.19, EJS 3.1, and the pg PostgreSQL client. It tracks buildings, rooms, tenants, lease contracts, rent payments, and utility bills. Key extensions include btree_gist (for GiST date-range exclusion constraints) and pgcrypto (for bcrypt password hashing).

3. Database Schema, Constraints, and Relationships

The schema consists of eight (8) base tables in schema public: property, room, tenant, lease, payment, utility_bill, app_user, and schema_migrations. Key constraints include:

  • Primary Keys: Serial integer PKs on all tables.
  • Foreign Keys: Enforced with default ON DELETE NO ACTION to preserve audit trails.
  • Check Constraints: 15 checks validating positive rates, valid date ranges, and status sets.
  • GiST Exclusion Constraint: ex_lease_no_overlap prevents overlapping ACTIVE leases on any room.
  • View: v_lease_summary dynamically computes payments and utility sums.

4. Backup Planning & Methodology

The backup plan (backup-plan.md) establishes logical backup via PostgreSQL’s native pg_dump utility using the Custom Archive Format (-Fc).

  • Format Justification: Built-in zlib compression (saving ~75% disk space), selective Table of Contents restoration via pg_restore, reorderable object restoration, parallel restoration (-j), and tamper resistance.
  • Recovery Objectives: RPO = 24 hours (daily logical dump) or < 15 mins (WAL PITR); RTO = < 15 minutes.
  • Cluster Role Handling: Roles exist cluster-wide and are omitted from single-database dumps; they are managed via roles-and-privileges.md.

10. Errors, Environmental Observations, and Technical Limitations

  • Safety Halt on Missing Live Database: In Phase 3, boardtrack_db was absent from the live PostgreSQL instance. Pursuant to DBA Safety Rule 3 ("Never initialize or reseed the original database"), live dumping was halted. All procedures and scripts were verified against the canonical BoardTrack baseline.
  • Cluster Role Omission: Single-database dumps omit global roles. Production setup requires applying roles-and-privileges.md.
  • RPO Limitation: Discrete dumps cannot recover transactions executed between the dump time and the incident. Production requires Continuous WAL Archiving (PITR).

11. Recommendations

  1. Deploy the declarative roles script in roles-and-privileges.md.
  2. Enable Continuous WAL Archiving in postgresql.conf for point-in-time recovery.
  3. Automate daily backups using activity-6-boardtrack/backup.ps1.
  4. Implement PostgreSQL Row-Level Security (RLS) on lease and payment for tenant defense-in-depth.
